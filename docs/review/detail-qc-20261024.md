## Implementasi

Empat tab berupa tautan baca native dengan parameter tab_qc; putaran dipilih melalui formulir GET dan tautan sebelumnya/berikutnya. Semua putaran dan macro penilaian lama tetap dirender, panel/putaran yang tidak dipilih diberi hidden. Pemilihan tampilan tidak membatasi masukan helper gabungan. Tidak ada handler JavaScript baru, endpoint transaksi, migrasi atau rumus baru.

Penilaian PK tetap melalui penilaian_dari_log dan macro bersama _penilaian_pk.html tanpa perubahan. Tabel Stok/transfer dan macro penilaian pada detail QC tetap identik dalam tes lama. Gabah memakai rata-rata batch dan total lamur header yang diperbarui layanan pencatatan lama dari seluruh sampel; status ditutup berasal ditutup_pada, bukan jumlah pemeriksaan. Alasan/waktu/petugas penutupan dibaca dari parent dan audit nyata.

app/web/detail_qc.py hanya menyusun parameter navigasi, konteks kembali internal, penanda data lama dan catatan terakhir yang tidak kosong beserta putaran asal. Tautan sumber memakai FK batch/tiket atau proses yang memang dibaca, tidak berdasarkan kemiripan nama/plat. Izin kategori, gudang efektif dan portal tetap dijalankan sebelum pembaca/penataan.

Template detail QC dan riwayat.css lama adalah komponen milik aplikasi. Penataan memakai stylesheet baru khusus halaman app/web/static/qc-detail.css. Macro bersama dari paket hanya dipanggil ulang, tidak disalin atau diedit; tidak ada perubahan pada folder vendored atau CSS Stok/proses bersama. URL stylesheet baru dan parameter qc=2 mengikuti cache aset aplikasi.

Baseline23tes PG lulus. Setelah implementasi63tes PG detail/penilaian/putaranPK/gabah/Stok/mutu/portal lulus,13kasus baru juga lulus dengan pemeriksaan terakhir.807tes non-PG lulus. Tes lama tidak diubah agar tetap menjaga fungsi yang sudah berlaku.
