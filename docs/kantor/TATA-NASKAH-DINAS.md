## I. PENDAHULUAN

### 1.1 Maksud dan Tujuan

Pedoman ini menjadi acuan baku pembuatan, penomoran, dan pengendalian naskah
dinas (surat dan dokumen resmi) PT Hadi Mulya Utama. Tujuannya: (a) menyeragamkan
format nomor surat dan dokumen di seluruh divisi; (b) memastikan setiap naskah
resmi bernomor unik, berurutan, dan tertelusuri; (c) mencegah nomor ganda atau
tidak konsisten; serta (d) menjadi pasangan dari Pedoman Kearsipan Digital dan
Panduan Tata Kelola Dokumen Digital.

### 1.2 Ruang Lingkup

Berlaku untuk seluruh naskah dinas perusahaan — surat keluar resmi, surat
keputusan, surat tugas, berita acara, dan dokumen tata kelola — yang dibuat oleh
seluruh divisi dan karyawan PT Hadi Mulya Utama.

### 1.3 Dasar

Undang-Undang No. 43 Tahun 2009 tentang Kearsipan; Undang-Undang No. 8 Tahun 1997
tentang Dokumen Perusahaan; kebijakan internal perusahaan; serta kelaziman tata
naskah dinas di Indonesia.

### 1.4 Definisi Singkat

- **Naskah dinas** — surat/dokumen resmi yang dibuat atas nama perusahaan.
- **Nomor surat** — identitas unik surat keluar, terbit berurutan per tahun.
- **Kode perihal** — singkatan jenis surat (mis. `CSR`, `SK`) di dalam nomor.
- **Register penomoran (Buku Agenda)** — daftar tunggal pencatat setiap nomor
  yang telah diterbitkan; menjadi sumber kebenaran urutan nomor.

---

## II. PRINSIP PENOMORAN

1. **Satu sumber nomor.** Semua nomor terbit dari satu Register Penomoran; tidak
   ada nomor yang dibuat sendiri-sendiri tanpa dicatat.
2. **Unik dan berurutan.** Tidak ada dua naskah dengan nomor sama; urutan tidak
   melompat tanpa alasan.
3. **Reset tahunan.** Nomor urut dimulai kembali dari `001` setiap awal tahun.
4. **Per kode+divisi.** Setiap kombinasi kode perihal & divisi memiliki deret
   urut sendiri per tahun (mis. `ST` dari HRGA terpisah dari `ST` OPS).
5. **Konsisten dengan penamaan file.** Penomoran berjalan seiring konvensi
   penamaan file pada Pedoman Kearsipan Digital.

## IV. FORMAT PENOMORAN SURAT

### 4.1 Pola baku

```
NNN / KODE / DIVISI / PT-HMU / BULAN(Romawi) / TAHUN
```

| Bagian | Arti | Contoh |
| :-: | :-- | :-: |
| NNN | Nomor urut 3 digit, per (kode+divisi), reset tiap tahun | `001` |
| KODE | Kode perihal / jenis surat (Bab III) | `SPPD` |
| DIVISI | Kode divisi/unit penerbit (§4.4) | `HR` |
| PT-HMU | Kode entitas perusahaan (tetap) | `PT-HMU` |
| BULAN | Bulan terbit, angka Romawi | `VII` |
| TAHUN | Tahun terbit, 4 digit | `2026` |

**Contoh lengkap:** `001/SPPD/HR/PT-HMU/VII/2026`
(Surat Persetujuan Pengunduran Diri, divisi HR, Juli 2026).

> Digit urut = **3 digit** (keputusan pemilik; sesuai Panduan Struktur Folder
> HRGA). Dokumen lama ber-2-digit (mis. SPPD Affifah `01/...`) tetap diterima
> sistem sebagai warisan, tidak dianggap salah.

### 4.4 Kode divisi/unit **(usulan — selaras kategori arsip)**

| Kode | Divisi | | Kode | Divisi |
| :-: | :-- | :-: | :-: | :-- |
| DIR | Direksi & Sekretariat | | MKT | Penjualan & Pemasaran |
| HRGA | SDM & Umum (`HR` = alias) | | PBJ | Pengadaan & Pemasok |
| KEU | Keuangan & Pajak | | IT | IT & Sistem |
| OPS | Operasional & Gudang | | | |

### 4.2 Tabel bulan Romawi

| I | II | III | IV | V | VI | VII | VIII | IX | X | XI | XII |
| :-: | :-: | :-: | :-: | :-: | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| Jan | Feb | Mar | Apr | Mei | Jun | Jul | Ags | Sep | Okt | Nov | Des |

### 4.3 Aturan

- Nomor urut 3 digit (`001`, `002`, … `012`, … `130`).
- Reset ke `001` setiap 1 Januari, terpisah per kombinasi kode+divisi.
- Bulan & tahun mengikuti tanggal penerbitan (bukan tanggal draf).
- Pemisah tanda strip `-`, tanpa spasi.

## V. FORMAT PENOMORAN DOKUMEN TATA KELOLA

Dokumen internal (pedoman, panduan, SOP korporat) memakai pola garis miring:

```
JENIS / KODE / PT-HMU / NO
```

| Bagian | Arti | Contoh |
| :-: | :-- | :-: |
| JENIS | `PDM` Pedoman · `PDN` Panduan · `SOP` · `IK` Instruksi Kerja | `PDM` |
| KODE | Kode ringkas isi dokumen | `TND` |
| PT-HMU | Kode entitas (tetap) | `PT-HMU` |
| NO | Nomor urut dokumen sejenis, 2 digit | `01` |

**Contoh:** `PDM/TND/PT-HMU/01` (Pedoman Tata Naskah Dinas — dokumen ini),
`PDM/KA-DIG/PT-HMU/01`, `PDN/TKD/PT-HMU/01`.

## VI. REGISTER PENOMORAN (BUKU AGENDA)

- Setiap penerbitan nomor **wajib** dicatat pada Register Penomoran (menggantikan
  buku agenda surat manual di kategori 01). Kolom minimal: **Nomor Lengkap ·
  Tanggal · Kode · Perihal · Tujuan/Pihak · Pembuat · Tautan File**.
- Nomor diterbitkan **berurutan otomatis**: sistem membaca nomor terakhir untuk
  (kode, tahun) lalu memberi nomor berikutnya — mencegah bentrok/ganda.
- Nomor yang batal dipakai ditandai **"batal"** (bukan dihapus), agar urutan
  tetap tertelusuri.
- Register menjadi rujukan saat memeriksa konsistensi surat masuk/keluar.

---

## VII. KONVENSI PENAMAAN FILE NASKAH BERNOMOR

Mengikuti Pedoman Kearsipan Digital (Bab IV), dengan penyesuaian untuk surat
bernomor agar mudah ditelusuri:

```
Jenis Dokumen - NNN-KODE-DIVISI-PT-HMU-BULAN-TAHUN - Perihal/Pihak.ext
```

**Contoh:** `Surat Tugas - 002-ST-HRGA-PT-HMU-VII-2026 - Eka Wahyu Nugrahani.docx`

- ⚠️ **Garis miring `/` DILARANG di nama file** (dianggap folder). Pada NAMA
  FILE, ganti `/` nomor menjadi tanda hubung `-`. Nomor asli (dengan `/`) tetap
  utuh di DALAM dokumen & register.
- Title Case, pemisah " - ", tanpa `(1)`/`copy`/`final`.

---

## VIII. KONSISTENSI & KOREKSI (PERAN ASISTEN DIGITAL)

Asisten arsip digital perusahaan menjaga penerapan pedoman ini secara otomatis:

1. **Generate nomor** saat surat/dokumen dibuat — langsung dari register, unik.
2. **Periksa** setiap naskah baru (dibuat staf atau masuk via scan/unggah):
   format nomor benar? urut? tidak ganda? nama file sesuai konvensi? kode
   perihal dikenali?
3. **Beri masukan** bila menyimpang, dengan usulan perbaikan yang konkret.
4. **Koreksi bila diizinkan** — memperbaiki nama file dan (bila dokumen dapat
   diedit) nomor di dalamnya; setiap koreksi tercatat pada log audit. Untuk
   surat resmi yang telah dikirim, koreksi hanya **diusulkan**, tidak diubah
   diam-diam.
