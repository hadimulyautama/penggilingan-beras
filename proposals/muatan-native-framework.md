# Muatan: canonical native pending framework

Local scope is exact bare `/muatan`, the actual G1 Pengiriman menu target.
`/barang-keluar/{perintah}/muatan`, `/selesai-muat`, all `?perintah`, `?item`,
`?semua`, `?buka` and other query variants stay native. They are not guessed
aliases and no outbound ID is invented. Root owns provider/head/registry wiring.

## Authority and reference cost

The existing route still executes `butuh_akun`, `boleh_catat(user)` and
`wajib(boleh or can_see_financials(user))` before the optional shape. The direct
helper consumes this already-computed `boleh`; it does not repeat that guard.
It uses the existing light `konteks_kerangka` navigation context instead of the
board/stock reads for its empty structural HTML. HTTP 401/403 is not swallowed.
X-Pindah 1 native data GET bypasses the helper completely.

Private global metadata `susun(request,akun,registry=registry)` evaluates exactly
one existing `muatan.boleh_catat(akun.user)` plus the native financial predicate.
It requires the current actual account, no portal and no mandatory password
change. It does not infer permission from VIEW, warehouse labels, OUT/G2 or a
sidebar link. Actual native semantics remain: Admin is read-only; Super or a
non-financial operator with actual G1/G2 predicate may record. The descriptor
only records a strict `can_record` boolean and current cap/context/session/source.
No names, role strings, actor IDs, warehouses, orders, balances or drafts.

This is not zero-SQL metadata: source short-circuiting means zero warehouse
queries for Admin/Super and potentially one G1 or two G1/G2 reference queries
for an Operator. No new guard per row, board, stock aggregate, device, network,
or TeraFlow read is introduced for global structure. These are source-based
potential counts, not measured runtime. Root must measure combined registry
cost. Direct helper additionally uses the already-approved light native nav
reads; no claim of zero total request queries or speedup.

## Native structure versus unknown content

The native title is Catat muatan; persistent H1 is Muat pengiriman with the
existing two help paragraphs. The pending chooser, table and summary keep
native structural labels. There are no fake kiriman/customer cards or blank
outbound rows; one full-width unread message is not a data row. Last column is
explicitly `Status sisa belum dibaca`: native later chooses Sisa versus Tidak
terkirim based on actual status. No claim this unknown label is the final one.

Buka lembar kiriman is disabled until real data. The two native muat/different
buttons are disabled, described by a clear data-needed reason, and appear only
in the record-enabled variant from the actual predicate outcome. Read-only
variant has neither transaction action. No form, input, name, action endpoint,
editor marker, actor, perintah or `#lembar-awal` exists in pending HTML.

The original native CSS is reused. A tiny style applies only under
`[data-muatan-native]` at <=600px so the pending table headers and single message
remain a table rather than the native per-record responsive card transformation.
It cannot affect the actual editor after pending is removed.

## Native controller, pending requests and integration boundary

The actual current controller is `app/web/static/muat-ringkas.js`, selected by
`app/web/templates/_lembar_muatan.html`, NOT the older package catat-muatan.js.
It reads `#lembar-awal` and `[data-lembar-muatan][data-editor-perintah]`, restores
`lembar-muatan-v1:<actual actor + view/look-as>:<CSRF>` with drafts, reasons,
uncertain/lastRequest and knownRows, and owns its navigation/beforeunload guard.
None of those markers, fields, storage reads or controller are in the pending
program. Do not initialize it with an empty fake `kiriman` object.

Only after the shared native reader finishes a fresh same-URL X1 HTML GET may
its original CSS/controller and JSON activate, once. That GET still executes
actual guards and `papan_selesai`/`papan` without change. Those old reads can take
a balance lock and query local ticket references; this proposal does not change
them, transaction rules, refresh, retries, keys or write endpoints. Opening the
pending page, retrying or abandoning the GET does not POST. The Root browser
test must verify that native sessionStorage data remains untouched while
pending and is restored under the same key only after original activation.

The factory chooses only breadcrumb presentation from a unique existing actual
Pengiriman sidebar link in the Root-bound private BM prototype (`/muatan` for
G1 versus `/barang-keluar` for other actual contexts). It does not use that link
as authority. Missing/ambiguous menu declines. Breadcrumbs are generated by the
existing pure native breadcrumb function with that exact menu address; no
warehouse or customer mapping. Bare Muatan keeps a native menu button.
