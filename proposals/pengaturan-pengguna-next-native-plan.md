No new row-level tenancy rule is invented for these master/account tables. A permission flag is supplied by the actual native caller after its positive check; a URL, menu label, four-view alias or matching integer cannot grant access. `X-Pindah:1` remains a native data GET even with inherited shell headers; only declared bare document/read variants are adopted. ## Proposed sequence and acceptance

1. Root reviews Group A flag/gate adapter and Group B hub/list proposal; independently reviewable data-free helpers can be prepared without changing shared callers. Fastest next safe leaf is `/pengaturan/alat` hub; practical next batch is fixed Settings detail variants with actual owner flags.
2. Group B lists establish current native facility link catalog; Group C consumes that provenance and explicit structural flags. Preserve redirects/404/missing-data native behavior.
3. Staff list before staff detail, with actual `is_super` tab flag and positive private link catalog. Keep all authority and one-time credential POST paths untouched.

Each family needs pure descriptor/permission/schema/source checks before Root wiring, then sequential synthetic native role/namespace/390/desktop/keyboard tests, separate delayed HTML/data, empty/filter-empty/error/retry/stale/deep link/Back/refresh and no POST during reads/navigation. Existing dirty native forms must still invoke their original guard; save-uncertain operation-key recovery must never be replaced by a blank shell. No all-page PASS, official CI or release claim follows from this inventory.
